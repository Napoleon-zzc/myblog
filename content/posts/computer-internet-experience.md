**背景**：突发奇想，利用学校机房的真实网络环境（校园网 WiFi + 独立有线网），结合理论进行一次真正的计算机网络实践。

## 环境拓扑与背景信息

* **客户端 A（我的笔记本）**：通过 WLAN 连接校园网
  * IPv4 地址：`10.0.97.60`
  * 子网掩码：`255.255.0.0`（即 `/16`）
  * 默认网关：`10.0.255.254`
  * 所属网段：`10.0.x.x`（校园网无线大内网）
* **客户端 B（机房电脑）**：以太网有线连接
  * IPv4 地址：`172.16.43.114`（后续更换为 `.132`）
  * 子网掩码：`255.255.255.0`（即 `/24`）
  * 默认网关：`172.16.43.1`
  * 所属网段：`172.16.43.x`（机房独立有线局域网）

## D1：跨网段通信与第一次实战

### 1. 理论验证：为什么不能“直接”通信？

一开始我以为连上同一个校园网就能直接互访，但看了 IP 配置后发现了问题：**两台机器不在同一个网段**。
根据计算机网络原理，主机通信时会先用自己的子网掩码和目的 IP 做与运算（AND）：

* 笔记本发现 `172.16.43.114` 与自己（`10.0.97.60/16`）不在同一个网段，因此不会直接通过 ARP 请求对方的 MAC 地址。
* 笔记本会把数据包交给自己的默认网关 `10.0.255.254`，由路由器进行**逐跳转发**。
* 机房电脑回包时，同理会将数据交给网关 `172.16.43.1`。加上学校网络通常有 VLAN 隔离和防火墙策略，所以底层网络是可达的，但端到端通信可能受阻。

### 2. 打通网络与 Wireshark 初探

万幸，学校的核心路由策略允许了 `10.0.x.x` 与 `172.16.43.x` 的互访。
在笔记本上执行 `ping 172.16.43.114` 成功。随后打开 Wireshark 抓包：

* 过滤 `icmp`，清晰地看到了 `Echo Request` 和 `Echo Reply` 的成对报文。

* 点开 IP 头部，观察源 IP 和目的 IP，印证了**跨网段通信时，MAC 地址在每一跳改变，但 IP 地址始终不变**的原理。

  > ICMP（Internet Control Message Protocol，互联网控制报文协议）是**网络层**的辅助协议，用来在 IP 网络中传递**控制信息和差错报告**，不用于传输用户应用数据。

### 3. 实战：局域网文件共享与 SMB 协议踩坑

既然 Ping 通了，下一步就是传文件。我尝试通过 `\\172.16.43.114` 访问机房电脑的共享文件夹。
**踩坑记录：**

* **问题**：机房电脑没有设置密码（空密码），但从笔记本访问时却一直弹窗提示要求输入账号密码。
* **原因**：Windows 出于安全考虑，默认启用了安全策略：*“账户：限制使用空密码的本地账户只能进行控制台登录”*。这意味着空密码账户不能通过网络（SMB 协议）进行身份验证。
* **解决**：
  1. 在机房电脑上按 `Win + R` 输入 `gpedit.msc`，进入“本地组策略编辑器”。
  2. 找到：**计算机配置 -> Windows 设置 -> 安全设置 -> 本地策略 -> 安全选项**。
  3. 将 *“账户：限制使用空密码的本地账户只能进行控制台登录”* 设为**已禁用**。
  4. 回到笔记本，用户名输入 `Administrator`，密码留空，成功进入并传输了文件。

## D2：故障排查与深度实践

### 1. 突发状况：换台机器就 Ping 不通了？

时隔一周，在同一个机房换了另一台机器（IP 变成了 `172.16.43.132`），从笔记本 `ping` 它时，居然**请求超时**了。
最初的疑惑：网段没变，网关一样，为什么上周行这周不行？

**排障思路复盘：**

1. **确认本机网络**：在 `.132` 上执行 `ipconfig`，IP/掩码/网关配置完全正确。
2. **反向测试**：用 `.132` 去 `ping` 机房网关 `172.16.43.1`，通了。说明物理链路和基础网络没问题。
3. **揪出元凶：Windows 防火墙**。
   * Windows 默认的防火墙策略是**拒绝外部的 ICMP 回显请求**（即默认不允许被 Ping）。
   * 上周的 `.114` 机器大概率是碰巧关闭了防火墙，或者之前有人配置了入站规则；而这台 `.132` 处于默认的安全防护状态。
   * **验证**：在 `.132` 的“Windows Defender 防火墙”中临时关闭专用/公用网络防火墙。笔记本瞬间 Ping 通！
   * **安全放行**：为了既能 Ping 通又能保持安全，在防火墙“高级设置” -> “入站规则”中，启用了 *“文件和打印机共享(回显请求 - ICMPv4-In)”*。

### 2. 进阶：如何利用双机环境深入学习网络？

难得有真实的双机跨网段环境，我整理了以下几个进阶实验方向：

* **网络诊断命令**：
  * `arp -a`：查看 ARP 缓存，验证跨网段通信时，本地 ARP 表里只有网关的 MAC 地址。
  * `tracert 172.16.43.132`：追踪路由，观察数据包经过了几个路由器。
  * `netstat -ano`：查看端口状态，确认 SMB（445端口）的 `ESTABLISHED` 状态。
* **Wireshark 抓包分析**：
  * 抓取 TCP 三次握手（过滤 `tcp.port == 445`），观察 `SYN -> SYN, ACK -> ACK` 的经典过程。
* **搭建简易服务**：
  * 在机房电脑用 Python 运行 `python -m http.server 8000`。
  * 在笔记本浏览器访问 `http://172.16.43.132:8000`，体验应用层 HTTP 协议的文件目录浏览。

## 总结

1. **同网段与跨网段**：同网段用 ARP 找对方 MAC 直接发帧；跨网段找网关 MAC，交由路由器逐跳转发。
2. **Windows 网络三座大山**：跨网段访问不通，**先查 IP 配置**，**再查防火墙（ICMP/端口）**，**最后查账号密码（SMB 认证）**。
3. **机房生存法则**：很多机房装有还原卡，重启后你的修改（如防火墙策略、密码）都会失效。如果修改了系统配置，建议操作完成后主动还原，做一个合格的“网管”。
4. **抓包神器**：Wireshark 是验证网络理论的最佳工具，一切理论在抓包结果面前都无所遁形。
